================================================================================
 adprofiler.py -- Detailed Version History
================================================================================

This file holds the full, detailed changelog for adprofiler.py that used to
live inline in the script's own docstring. Moved out starting at v0.5.8 to
stop the script itself from carrying its entire version history around --
the script's own docstring now keeps a one-line summary per entry, this
file keeps the complete detail (root causes, what was verified, why a
decision was made a particular way) for anyone who wants it.

    0.7.1 - Requires schema v40 (schema_migration_v40.sql). The tombstone /
            deleted-object lifetime now records its source in
            ad_domain.tombstone_lifetime_source: msDS-DeletedObjectLifetime,
            tombstoneLifetime, not_set (the Directory Service object was read
            and neither attribute is set: the MS-ADTS 60-day default applies)
            or unreadable. An unreadable object no longer yields an assumed
            60 days -- the lifetime is stored as NULL (is_default NULL) and
            client.tombstone_lifetime_days keeps its last known value.
            Before, both cases produced "assumed 60 days", so plugin 4011
            couldn't tell a real 60-day lifetime from a value nobody read.
    0.7.0 - Requires schema v39 (schema_migration_v39.sql). New, opt-in
            --sysvol: reads Group Policy content from the SYSVOL and
            NETLOGON shares over SMB (impacket; read-only; same account;
            --sysvol-kerberos for Kerberos-only environments, --smb-host
            to use another host, --sysvol-max-script-files to cap script
            scanning). New module sysvol_collector.py parses gpt.ini,
            GptTmpl.inf (security template), Registry.pol (PReg format),
            audit.csv (advanced audit policy) and Group Policy
            Preferences XML (Groups, ScheduledTasks, Services,
            DataSources, Drives, Printers), and scans GPO script folders
            and NETLOGON for credential patterns. Stored in
            gpo_setting_edge / gpo_preference_item_edge /
            sysvol_script_edge (versioned edges, synced in this run's
            transaction under a savepoint), ad_gpo_sysvol (per-GPO read
            result) and sysvol_collection_status. Views
            v_gpo_dc_application (which GPOs apply to each DC, with
            precedence: links, enforcement, block inheritance, computer
            settings disabled, Apply Group Policy security filtering) and
            v_dc_effective_gpo_setting (each DC's winning value per
            setting). Secrets are never stored: cpassword values are only
            detected, credential-named string registry values are stored
            as '<redacted>', and script findings record pattern names and
            line numbers only. Never fatal: an unreachable share leaves all
            previously collected Group Policy data unchanged
            (status 'failed'); an unreadable GPO folder or NETLOGON keeps
            its previous rows.
    0.6.0 - Requires schema v38 (schema_migration_v38.sql); run once with
            --full-rescan afterwards so existing objects get the new
            columns. Expect, on the first 0.6.0 run: one new version per
            user (accountExpires is now collected and is set on every
            user), one per DNS zone (zone settings are now versioned, see
            (8)), one for the domain object (new derived settings) and one
            per Enterprise CA (cACertificate). Collector changes:
            (1) Security descriptor control flags. parse_security_descriptor()
            also returns the SD header's Control field; every place that
            stores owner_sid now stores directory_object.sd_control too
            (0x1000 SE_DACL_PROTECTED = inheritance disabled).
            (2) Users: altSecurityIdentities, accountExpires, and (probed)
            msDS-AssignedAuthNPolicySilo / msDS-AssignedAuthNPolicy and the
            cleartext-password attributes userPassword, unixUserPassword,
            msSFU30Password, os400Password. Their VALUES are replaced by
            "<redacted: N value(s)>" before anything is stored or logged;
            only the names of the populated ones reach
            cleartext_password_attributes.
            (3) Computers: altSecurityIdentities, managedBy, msDS-KrbTgtLink,
            the cleartext-password attributes, and (probed) the dMSA
            attributes msDS-ManagedAccountPrecededByLink /
            msDS-DelegatedMSAState. is_gmsa / is_dmsa come from targeted
            objectClass searches (objectGUID only) applied in place --
            objectClass is still not bulk-collected.
            (4) RODC password replication policy -> rodc_prp_edge
            (msDS-RevealedList / msDS-RevealOnDemandGroup /
            msDS-NeverRevealGroup; DN-String values decoded; one sync per
            run; an RODC whose read fails keeps its edges).
            (5) ad_domain: Recycle Bin state, schema objectVersion,
            forest/domain updates revisions, SCRIL hash rolling
            (msDS-ExpirePasswordsOnSmartCardOnlyAccounts, probed), KDS
            root key count, LAPS attribute schemaIDGUIDs (formatted like
            acl_edge.object_type_guid), authentication policy silos and
            policy count, forest root DN (RootDSE rootDomainNamingContext).
            All folded into the domain's derived settings, so a change
            versions the domain.
            (6) ad_backup_status: last backup per naming context from the
            NC head's dSASignature replication metadata, overwritten each
            run (domain, configuration, schema, DomainDnsZones,
            ForestDnsZones).
            (7) GPOs: gPCFileSysPath and flags; each GPO's security
            descriptor now goes to acl_edge / owner_sid / sd_control.
            (8) DNS zones: forest-wide zones (ForestDnsZones) collected too,
            each partition reconciled separately; ad_dns_zone.partition;
            has_wildcard_record / has_wpad_record from a one-level search
            per zone; zone ACLs to acl_edge (DNS collection moved before
            the single acl_edge sync). allow_update and the record flags
            are read before the zone is versioned and stored in
            attributes_full under "adprofiler:zoneSettings", replacing the
            old in-place UPDATE, so a zone switched to nonsecure updates
            now leaves history (plugin 11018).
            (9) KDS root keys -> ad_kds_root_key (metadata only, never
            msKds-RootKeyData), plus the container's and each key's ACL. A
            low-privileged account may see no key objects at all.
            (10) AD FS DKM objects -> ad_adfs_dkm_object; the key itself
            (thumbnailPhoto) is never read -- key_readable_by_collector
            records whether a presence filter on it matched. Skipped when
            there is no CN=ADFS container.
            (11) Root CA (CN=Certification Authorities) and AIA certificates
            -> ad_pki_certificate_store. Certificate parsing is shared
            (parse_certificates()) and now also records not_valid_before,
            key_algorithm, key_size and signature_hash_algorithm -- for
            NTAuth too.
            (12) Enrollment services: cACertificate -> ca_certificates,
            msPKI-Enrollment-Servers (probed) -> enrollment_servers.
            (13) Certificate templates: msPKI-Minimal-Key-Size,
            msPKI-Private-Key-Flag.
            (14) Trusts: supported_encryption_types column.
            (15) Schema classes: defaultSecurityDescriptor and
            lDAPDisplayName.
            Every new LDAP read is non-fatal: a failure is logged and
            recorded as unknown (NULL, or edges carried forward).
    0.5.16 - Requires schema v37 (schema_migration_v37.sql); run once with
            --full-rescan afterwards. (1) sIDHistory decoded to S-1-5-...
            strings. ldap3 has no formatter for it, so it was stored as
            base64/garbled text and plugins could not classify SID-history
            entries. (2) msDS-KeyCredentialLink parsed (KEYCREDENTIALLINK_BLOB,
            [MS-ADTS] 2.2.20) into ad_user/ad_computer.key_credentials: key
            id, device id, usage, source, creation time, flags -- what tells
            a device's own key from an added "shadow credential". (3)
            dSHeuristics dwAdminSDExMask (character 16) recorded as
            ad_domain.dsheuristics_admin_sd_ex_mask. (4) The forest's
            sPNMappings are read and used to resolve delegation target SPNs
            (falling back to the default HOST alias set) and stored as
            ad_domain.spn_mappings. (5) RBCD trustees that aren't collected
            objects (well-known, foreign or orphaned SIDs) are kept, by SID,
            in rbcd_unresolved_trustee_edge instead of being dropped. (6)
            AD sites are collected before GPO link resolution and their
            gPLink is included, so site-level GPO links are recorded.
    0.5.15 - Requires schema v36 (schema_migration_v36.sql); run once with
            --full-rescan afterwards so existing objects get the new
            columns. Collector fixes found by the per-plugin review:
            (1) RODCs counted as domain controllers. is_domain_controller
            was SERVER_TRUST_ACCOUNT only; RODCs carry
            PARTIAL_SECRETS_ACCOUNT instead and were treated as ordinary
            computers (flagged for their default delegation and primary
            group, skipped by DC checks). New ad_computer.is_read_only_dc.
            (2) Primary-group membership recorded. primaryGroupID is never
            listed in a group's member attribute, so Domain Users looked
            empty, an FGPP applied to it covered nobody, and an account
            whose primary group was privileged wasn't a member anywhere
            membership is evaluated. Added to group_member_edge with
            is_primary_group = TRUE. (3) ad_interval_to_seconds() keeps 0 as
            0 for minPwdAge, lockoutDuration and the observation window (0
            means "no limit" only for maxPwdAge); "minimum password age is
            zero" could never be detected. (4) dNSProperty's
            DSPROPERTY_ZONE_ALLOW_UPDATE is read as a single byte; requiring
            four bytes made it NULL for every zone. (5) ad_domain.dns_root
            holds the DNS name, not the DN. (6) Newly collected:
            msPKI-RA-Signature and msPKI-Cert-Template-OID on templates,
            msPKI-Cert-Template-OID/displayName on issuance policies (ESC13
            matching), userPrincipalName on computers/gMSAs,
            msDS-AllowedToActOnBehalfOfOtherIdentity on users (RBCD on
            krbtgt). (7) Owners of every adminCount=1 user, group and
            computer are read. (8) Constrained-delegation target SPNs
            resolve through the default HOST alias set, as the KDC does, so
            cifs/<host> on a computer registering only HOST/<host> is no
            longer a "ghost" SPN. (9) Deny ACEs in an RBCD descriptor are
            no longer recorded as delegation trustees. v_privileged_principal
            now also counts an inherit-only ACE on the domain root (or an
            OU above a DC) reaching computer objects as Tier 0 control
            whenever some DC is not AdminSDHolder-protected. Trust objects
            now also collect msDS-SupportedEncryptionTypes (plugin 7003).
            Owners of certificate templates and CA objects are now stored
            (their security descriptors were already read; the owner was
            discarded).
    0.5.14 - Requires schema v35 (schema_migration_v35.sql, which only
            widens control_evidence_fact.change_status for adaudit.py).
            (1) Edge payload changes are now versioned. sync_edges()
            compared edge keys only, so once a GPO link existed, later
            disabling or enforcing it (or changing its link order) was
            never recorded; same for a gMSA password reader's access
            mask. sync_edges() takes payload_cols: an edge whose key is
            unchanged but whose tracked payload differs is closed and
            reopened. Used for gpo_link_edge (link_order, link_enabled,
            link_enforced) and gmsa_password_reader_edge (access_mask,
            ace_type). (2) Deletions outside the domain partition are
            detected. collect_deleted_objects() only searches the domain
            NC's Deleted Objects container, so deleted certificate
            templates, CAs, NTAuth, sites, subnets, schema objects,
            DisplaySpecifiers, cert OIDs and DNS zones kept their typed
            rows open forever. Those classes are fully re-enumerated
            each run, so reconcile_absent_objects() marks any previously
            current object under the same container that wasn't seen
            this run as deleted -- only after the enumeration completed,
            and only if the container itself is still present on this
            DC (an absent container or a referral returns nothing and
            must not read as "all deleted"). (3) Domain-level settings
            read from other objects -- dSHeuristics (anonymous access,
            UPN/SPN uniqueness), tombstone lifetime, functional level,
            DFSR migration state, LAPS schema presence -- are folded
            into the domain object's attributes_full under one synthetic
            key (DERIVED_DOMAIN_SETTINGS_KEY), so a change to any of
            them versions the domain object and rewrites ad_domain.
            Before, they only updated when an attribute of the domain
            object itself changed. Expect one 'modified' domain version
            on the first run with this version (the key is new); it
            also fills dsheuristics_uniqueness without --full-rescan.
    0.5.13 - Requires schema v34 (schema_migration_v34.sql). Three fixes:
            (1) ACE inheritance flags are now collected. An ACE carrying
            INHERIT_ONLY_ACE grants nothing on the object it sits on --
            e.g. "Full Control over descendant Computer objects"
            delegated at the domain root -- but the flag was discarded,
            so it read as Full Control over the domain root itself.
            acl_edge.inherit_only / inherited_object_type_guid now
            record it; when several ACEs share one edge key the edge is
            inherit-only only if all of them are. Rows collected before
            v34 are backfilled in place on the next run (not closed and
            reopened, which would make change-detection plugins report
            every existing grant as new); a real later change in the
            flags is versioned normally (close + reopen). (2) A security
            descriptor that couldn't be read or parsed no longer closes
            that object's ACL edges: the object's currently open edges
            are carried forward unchanged and a warning names how many,
            since a failed read means the ACL is unknown, not empty.
            (3) Objects restored from the AD Recycle Bin are visible
            again. They keep their objectGUID, so they came back as the
            same directory_object row still flagged is_deleted, and
            repair_orphaned_deleted_typed_rows() closed their typed row
            on every run. Any object confirmed live in the current run
            now has its deleted flag cleared first, and is logged.
    0.5.12 - LDAP failures are no longer silently treated as empty
            results. The connection used ldap3's default
            raise_exceptions=False, under which a failed search returns
            nothing rather than raising, and ldap3's paged_search
            generator simply stops on a failed page -- so a DC answering
            busy/unavailable/time-limit-exceeded partway through a
            collection produced a truncated result set, the run
            committed as 'succeeded', and sync_edges() closed every edge
            (group memberships, SPNs, delegations, ACLs) for the objects
            it never saw. The non-fatal `except LDAPException` wrappers
            around optional steps never fired for the same reason, and
            the capability probe's view_deleted_objects check always
            passed. Every search now goes through ldap_search() /
            ldap_paged_search(), which check the LDAP result code:
            noSuchObject and referral mean "not present" (unchanged
            behavior for optional containers); busy, unavailable and
            timeLimitExceeded are retried with backoff (4 attempts);
            operationsError and dropped/timed-out connections trigger a
            rebind and retry (a paged search restarts from page one and
            skips entries already processed, since AD's paging cookie
            doesn't survive a new connection); anything else, or
            exhausted retries, raises LDAPCollectionError, which aborts
            the run, rolls back the transaction and marks sync_run
            'failed' with the error. Behavior change to note: a bind
            account that is actively refused (rather than shown an empty
            result) on CN=Deleted Objects now fails the capability probe,
            as the probe always intended.
    0.5.9 - Fixed a real, confirmed schema bug found in production:
            unresolved_delegation_target_edge.edge_id was created as a
            plain "bigint NOT NULL" with no auto-generation mechanism
            at all -- every other edge table gets its edge_id via a
            separate ALTER TABLE ... ADD GENERATED ALWAYS AS IDENTITY
            statement after CREATE TABLE, and that statement was simply
            never added for this one table (schema_migration_v29.sql,
            when the table was first created). Confirmed by direct
            comparison against delegation_edge's correct definition.
            Sat dormant since v29 because no test lab or client run had
            hit a genuine unresolved ("ghost") delegation target until
            Robert Morris University did, at real production scale
            (30,014 active SPNs) -- the INSERT failed with a NOT NULL
            violation on edge_id, rolling back the entire collection
            run. Fixed via schema_migration_v32.sql (EXPECTED_SCHEMA_
            VERSION bumped to 32 accordingly) using the exact same
            GENERATED ALWAYS AS IDENTITY syntax every other edge table
            uses, not a different auto-increment mechanism. Verified by
            reproducing the exact failure against the un-fixed schema
            first, then confirming the identical insert succeeds
            cleanly after the fix -- also traced sync_edges()/open_edge()
            to confirm edge_id is never explicitly referenced in the
            INSERT (built dynamically from a dict that never includes
            it), so the schema-only fix is fully sufficient with no
            corresponding code change needed.
    0.5.8 - Added schema version tracking (schema_migration_history table,
            EXPECTED_SCHEMA_VERSION constant, check_schema_version()).
            Compares the database's actual applied-migration version
            against what this script expects via a single integer
            comparison, replacing prose-based version detection that
            had already gone stale once (see v0.5.7): a hardcoded
            error message told a real client to "Apply schema.sql and
            schema_migration_v2.sql," filenames that stopped being
            accurate many migrations before that client hit the
            message. Kept the existing structural check (table/column/
            function presence) as a backstop rather than a replacement
            -- the version number gives precise, fast diagnosis for the
            common case (a database simply behind on migrations); the
            structural check remains the safety net for the rarer case
            of a schema altered outside the approved migration files,
            where the version number could claim to be current while
            the actual structure doesn't match it. Four distinct
            outcomes, each with its own precise message: "behind"
            (tells you exactly which migration files to apply, by
            number), "ahead" (tells you to upgrade the script instead),
            "untracked" (database predates version tracking entirely,
            combines the generic guidance with the structural check's
            specific findings), and "match with structural problems"
            (distinguishes tampering from a missing migration -- the
            version says you're current, so something else changed the
            schema, not that a migration was skipped). All five
            branches (behind/ahead/untracked/match-clean/match-tampered)
            verified against real staged databases before shipping,
            not just reasoned through.
    0.5.7 - Fixed a long-standing stale error message: the schema-
            incompatibility failure told users to "Apply schema.sql and
            schema_migration_v2.sql" -- filenames that stopped being
            accurate many migrations ago (the actual files are
            schema_init.sql and whatever schema_migration_vNN.sql is
            current). This sent a real client chasing the wrong file
            when their database was actually just missing a later
            incremental migration. New message correctly warns against
            re-running schema_init.sql against a populated database
            (data-loss risk) and points at the incremental migration
            path instead.

            DomainDnsZones partition). Parses dNSProperty per [MS-DNSP]
            2.3.2.1 to extract DSPROPERTY_ZONE_ALLOW_UPDATE. Supports
            plugin 4025 (nonsecure dynamic updates).
    0.5.5 - Domain controller computer-object ownership scanning (targeted
            owner-only SD read, same low-cost profile as domain root/
            AdminSDHolder -- not full ACE scanning). Supports plugin 4023.
    0.5.4 - ADCS ACL collection: certificate template objects, CA
            (pKIEnrollmentService) objects, each CA's own computer
            object (cross-referenced via dNSHostName), and the Public
            Key Services / Certificate Templates / Enrollment Services
            containers, plus NTAuthCertificates (already collected as
            an object, now also ACL-scanned). Enables ESC4 (template
            ACL misconfiguration), ESC5 (PKI infrastructure object ACL
            misconfiguration), and ESC7 (CA object ACL misconfiguration)
            detection -- confirmed LDAP-native for all three before

            loop to after this new ADCS section -- see the comment left
            in both spots for why a second, separate sync call would
            have been a real bug (already proven once this session),
            not a style choice.
    0.5.3 - NTAuthCertificates collection (ad_ntauth_store). New
            dependency: cryptography, for X.509/DER parsing -- this
            project's first need for it, unlike security descriptor
            parsing (impacket) which already existed for ACL
            collection. Every certificate in the forest-wide
            NTAuthCertificates object (trusted for smart card/
            certificate-based domain logon) is parsed and cross-
            referenced against known Enrollment Service CAs by plugin
            6005, surfacing orphaned or unauthorized entries. Requires

    0.5.2 - Added admin_count to computer collection (previously users
            and groups only). Extends plugins 3021 (missing
            AdminSDHolder marker) and 5007 (privileged object owned by
            an unprivileged account) to cover computers -- both had
            explicitly documented this as a known gap since they were
            first written. Requires schema_migration_v23.sql.
    0.5.1 - gMSA password-reader tracking. No new object collection --
            gMSAs are a schema subclass of computer (confirmed against
            Microsoft's own [MS-ADSC] spec), already returned by the
            existing computer collection pass. Added
            msDS-GroupMSAMembership to COMPUTER_ATTRS (a full security
            descriptor, same format as RBCD's own delegation attribute,
            reused here for a different purpose: who can retrieve the
            gMSA's computed password), with the same base64-encoding
            special case in build_attributes_full() that RBCD's
            attribute already needed, since normalize_value()'s generic
            bytes fallback wasn't trusted for this syntax type without
            direct verification against a real DC. Parsed into a new
            dedicated table, gmsa_password_reader_edge -- deliberately
            not reused into acl_edge or delegation_edge; see
            resolve_gmsa_password_readers()'s own docstring for why.
            Requires schema_migration_v22.sql.
    0.5.0 - Organizational Units: full typed-table collection (ad_ou),
            matching every other object class rather than a one-off.
            gPLink (on both OUs and the domain object) resolved into a
            new gpo_link_edge many-to-many table -- closes the
            "orphaned GPO" and "which GPOs actually apply where" gaps
            this project previously had zero visibility into. ACL
            collection extended from domain root + AdminSDHolder only
            to also cover every collected OU -- OU delegation
            (GenericAll/WriteDacl/etc. over everything within it) is
            one of the more common real-world privilege-escalation
            paths, and this project had no visibility into it before.
            Requires schema_migration_v21.sql.
    0.4.2 - Fixed client.domain_fqdn being populated with args.dc_host
            (the specific domain controller hostname typed at
            --dc-host, e.g. 'df-dc-01.forge.local') instead of the
            actual AD domain FQDN ('forge.local') -- close enough to
            look right, wrong enough to break any lookup by the real
            domain name. Found via entra_graph_collector.py's
            --domain-fqdn, which needs the real domain name to find
            the right client row. New base_dn_to_fqdn() derives the
            correct value from base_dn's own DC= components instead,
            which every run already resolves correctly regardless of
            what hostname was passed at the command line. Existing
            production client rows are NOT automatically corrected --
            see the accompanying one-time UPDATE statement.
    0.4.1 - Added --full-rescan: forces every object to get a fresh
            version + typed-columns write this run, even when its raw
            AD attributes are unchanged. Closes a real gap found on the
            first live run against forge.local after v0.4.0's mail/
            proxy_addresses/when_created columns shipped -- every
            existing object's when_created (and, separately, well-
            known-SID resolution for foreign security principals) came
            back NULL/unresolved, because the change-detection path
            that recomputes typed columns only runs when an object's
            raw attributes actually differ from what's already stored.
            None of forge.local's 146 objects had genuinely changed
            since baseline, so none of them ever got the new columns
            backfilled -- not a data-quality bug, but a gap in how
            newly-added derived data reaches already-baselined objects.
            Recorded honestly as change_kind='rescanned' (new enum
            value), not 'modified', since nothing in AD actually
            changed. Requires schema_migration_v19.sql.
    0.4.0 - Added mail/proxyAddresses collection for users, and
            whenCreated promoted to a first-class when_created column
            for users, computers, and groups (previously fetched and
            stored only inside attributes_full's raw JSONB, never
            surfaced as a queryable column). Driven by three new
            "inventory"-type plugins in adaudit.py v0.7.0 (a parallel
            plugin type for snapshot listings, not findings) that
            needed both. Requires schema_migration_v18.sql.
    0.3.2 - Closed a real gap found during a follow-up ACL plugin-
            generation pass: parse_security_descriptor() has computed
            each scanned object's owner SID since v0.3.0, but nothing
            ever persisted it -- silently discarded every run.
            Ownership is a real, distinct security-relevant fact
            (BloodHound's "Owns" edge: an owner implicitly holds
            WRITE_DAC-equivalent rights regardless of what the DACL
            itself says). Added directory_object.owner_sid (generic,
            not scoped to one object type, matching object_sid's own
            precedent) and threaded it through for both objects this
            project currently scans ACLs for (domain root,
            AdminSDHolder). Requires schema_migration_v17.sql.
    0.3.1 - Added Enterprise Domain Controllers (S-1-5-9) to
            WELL_KNOWN_SIDS, found via the first real run of ACL
            collection against forge.local: this well-known SID
            correctly gets collected as a foreignSecurityPrincipal
            object (that part always worked), but had no display name
            mapped, so plugin 5001 showed it as a raw SID string
            instead of a readable name. No new collection needed --
            purely a display fix; will self-correct on the next
            collection run via the same change-detection mechanism
            already used for every other typed-column update.
    0.2.6 - Fixed a real, confirmed display bug found against a real run:
            the per-category log line inside collect_object_class
            ("<label>: N object(s) processed (X new, Y changed this
            pass)") was printing the shared, run-WIDE cumulative
            stats.created/stats.modified counters directly, not a count
            scoped to that category. Invisible in a typical no-op delta
            run (0 either way), but became obviously wrong once any
            earlier category had genuine changes: every subsequent
            category's line kept echoing that same stale cumulative
            number, including categories with zero actual objects (e.g.
            a "trusts" line reporting "2 changed" while also reporting
            "0 trusts object(s) processed"). The shared counters
            themselves were never wrong -- the final Run Summary's true
            whole-run totals were always correct -- only this one
            per-category line was reading the wrong value. Fixed by
            snapshotting the counters at function entry and reporting
            the delta. No schema change, no plugin change.
    0.2.5 - Systematic gap-analysis pass against BloodHound/PingCastle's
            actual finding catalogs. Two new collection additions found
            necessary: (1) foreignSecurityPrincipal objects were never
            collected at all -- well-known SIDs (Everyone, Anonymous
            Logon, Authenticated Users) added to a group's membership
            are represented as real AD objects under
            CN=ForeignSecurityPrincipals, not literal accounts. This
            directly explains the "N unresolved (not a collected
            object)" line present in every single collection run
            throughout this entire project. New minimal typed table
            ad_foreign_security_principal, added to KNOWN_TYPED_TABLES
            so it participates in the existing deletion-detection
            machinery automatically. (2) dSHeuristics 7th character
            (anonymous LDAP access, confirmed against MS-ADTS and DISA
            STIG V-243503) folded into the existing Directory Service
            object query already used for tombstone lifetime -- no new

    0.1.9 - Fixed a real, confirmed follow-on to the v0.1.8 deletion bug.
            v0.1.8 only closes a typed table row at the moment a
            deletion is first detected -- it has no way to revisit an
            object already marked directory_object.is_deleted=TRUE by an

            reconciliation step that runs on EVERY invocation regardless
            of run_type (not gated to delta runs, since it checks
            already-persisted state rather than doing a fresh LDAP
            query): any directory_object row with is_deleted=TRUE whose
            typed table still shows valid_to IS NULL gets repaired,
            regardless of when or by which collector version the
            deletion was originally detected. Verified directly against
            a staged stuck-orphan scenario (repairs correctly, and is
            idempotent -- a second run finds nothing left to fix) and
            confirmed harmless against the existing fresh-deletion
            scenario in test_harness.py (0 repairs needed there, as
            expected, since that deletion is caught within the same run
            that has the v0.1.8 fix). Also fixed a UUID/text type
            mismatch caught during this same testing: psycopg2 needs an
            explicit ::uuid[] cast for a Python list of GUIDs passed to
            = ANY(%s), or Postgres defaults to interpreting it as text[]
